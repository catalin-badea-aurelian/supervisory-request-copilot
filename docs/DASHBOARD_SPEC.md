## 1. Purpose

The dashboards give an **independent, current view of risk and of the data behind it**. They answer one question first:

> When an indicator moves, is it a **risk event** or a **data event**?

**Risk overview** shows what moved. **Data risk (BCBS 239)** shows whether the data can be trusted. **Request operations** shows how the oversight team handles requests.

Everything is code: mart views and LookML are generated from the domain pack, and the dashboards are LookML dashboards in Git.

## 2. Physical layer: mart views (`spb_marts`)

Generated by `make views` from the domain pack. Metric marts use the **independent** (raw-source) templates: the oversight team's own figures, not the parent group's.

| View | Grain | Columns |
|---|---|---|
| `mart_ewi_components` | month × country × MCC group | period_month, merchant_country, mcc_group, settled_volume_eur, transaction_count, chargeback_amount_eur, chargeback_count, fraud_loss_eur, refunded_amount_eur |
| `mart_ewi_monthly` | metric × month × country | period_month, merchant_country, metric_id, metric_version, value, amber, red, direction, rag_status, mom_change |
| `mart_dq_status` | check × metric × month × country (latest scan per as-of) | as_of, period_month, merchant_country, metric_id, check_id, check_name, principle_refs, status, measured, threshold, run_type |
| `mart_bcbs239_scorecard` | principle (latest scan) | as_of, principle_no, principle_name, checks_total, pass, warn, fail, pass_rate |
| `mart_timeliness` | table × month | as_of, table_name, partition_month, expected_rows, loaded_rows, completeness_pct, last_loaded_at, status |
| `mart_metric_catalog` | metric version | metric_id, version, owner, status, has_independent_path, lineage_documented, reconciles_to, changed_at |
| `mart_requests` | request | request_id, title, received_at, deadline, delivered_at, status, on_time, g2_escalations, accepted_findings, est_cost_eur, duration_s |
| `mart_gate_decisions` | decision | request_id, gate, decision, role, ts |

`mart_ewi_components` holds **additive** components only; ratios are defined in LookML (section 3). `mart_ewi_monthly` holds pre-computed values with RAG status at month × country, for heatmaps and breach lists, including non-additive metrics such as top-10 concentration.

## 3. Semantic layer: LookML

Generated by `make lookml` into `looker/`. Every generated file starts with `# GENERATED FROM domain pack <id>@<version> — DO NOT EDIT`. Manual adjustments go into `looker/refinements/` using LookML refinements (`view: +name`).

### 3.1 Project layout

```
looker/
├── manifest.lkml                 # constants (e.g. GCP project), project settings
├── spb_oversight.model.lkml      # connection, includes, explores
├── views/                        # one generated view per mart
├── refinements/                  # hand-written refinements, never overwritten
└── dashboards/                   # risk_overview, data_risk, request_operations
```

### 3.2 Explores

| Explore | Base view | Purpose |
|---|---|---|
| `ewi_components` | `mart_ewi_components` | Re-aggregatable indicators at any grain (month, quarter; country; MCC) |
| `ewi` | `mart_ewi_monthly` | RAG status, breaches, heatmaps |
| `dq_status` | `mart_dq_status` | Check results by check, month, country |
| `bcbs239` | `mart_bcbs239_scorecard` | Principle scorecard |
| `timeliness` | `mart_timeliness` | Load completeness by table and month |
| `metric_catalog` | `mart_metric_catalog` | Governance indicators, lineage coverage |
| `requests` | `mart_requests` joined to `mart_gate_decisions` | Request operations |

Every explore carries the description "Synthetic data — fictional entity."

### 3.3 Generated view (illustrative)

```lookml
# GENERATED FROM domain pack payments@1.3.0 — DO NOT EDIT
view: ewi_components {
  sql_table_name: `@{GCP_PROJECT}.spb_marts.mart_ewi_components` ;;

  dimension: pk {
    primary_key: yes
    hidden: yes
    sql: CONCAT(CAST(${TABLE}.period_month AS STRING), '|', ${TABLE}.merchant_country, '|', ${TABLE}.mcc_group) ;;
  }

  dimension_group: period {
    type: time
    timeframes: [month, quarter, year]
    datatype: date
    sql: ${TABLE}.period_month ;;
  }

  dimension: merchant_country {
    type: string
    sql: ${TABLE}.merchant_country ;;
  }

  dimension: mcc_group {
    type: string
    sql: ${TABLE}.mcc_group ;;
  }

  measure: settled_volume_eur {
    type: sum
    sql: ${TABLE}.settled_volume_eur ;;
    value_format_name: eur_0
    description: "settled_volume_eur v1.0.0 | Sum of settled transaction amounts (EUR)"
    tags: ["metric_id:settled_volume_eur", "metric_version:1.0.0"]
  }

  measure: chargeback_amount_eur {
    type: sum
    sql: ${TABLE}.chargeback_amount_eur ;;
    value_format_name: eur_0
    description: "chargeback_amount_eur v1.0.0 | Chargebacks attributed to the original transaction month"
    tags: ["metric_id:chargeback_amount_eur", "metric_version:1.0.0"]
  }

  measure: chargeback_rate_value {
    type: number
    sql: SAFE_DIVIDE(${chargeback_amount_eur}, ${settled_volume_eur}) ;;
    value_format_name: percent_2
    description: "chargeback_rate_value v1.2.0 | Value of chargebacks on settled transactions / value of settled transactions, by transaction month"
    tags: ["metric_id:chargeback_rate_value", "metric_version:1.2.0"]
  }
}
```

The rate is always `SUM(numerator) / SUM(denominator)` at the grain the user picks, which is the same formula as the copilot's template. This is what the consistency test (FR-D6) checks. The snippet is illustrative; the generator must produce whatever Looker validates without errors or warnings.

### 3.4 Generator rules

- One measure per glossary metric, with the glossary formula, unit-based value format, description `"<id> v<version> | <definition>"`, and tags `metric_id:` and `metric_version:`.
- Allowed dimensions per metric come from `allowed_dimensions` in the domain pack; nothing else is exposed.
- Hidden helper measures for components that are not glossary metrics.
- Unit tests (no Looker needed): every glossary metric has a measure; formulas match the templates; descriptions and tags match the pack version; generated files carry the header and an unchanged content hash.

### 4.4 LookML dashboard (illustrative)

```lookml
- dashboard: risk_overview
  title: "Risk overview"
  layout: newspaper
  preferred_viewer: dashboards-next
  description: "Independent early-warning indicators. Synthetic data, fictional entity."
  filters:
  - name: period
    title: "Period"
    type: field_filter
    default_value: "12 months"
    model: spb_oversight
    explore: ewi
    field: ewi.period_month
  elements:
  - name: cb_rate_heatmap
    title: "Chargeback rate (value) by country and month"
    model: spb_oversight
    explore: ewi
    type: looker_grid
    fields: [ewi.merchant_country, ewi.period_month, ewi.value]
    pivots: [ewi.period_month]
    filters:
      ewi.metric_id: chargeback_rate_value
    listen:
      period: ewi.period_month
```

Illustrative only. The working approach is: prototype or export from Looker, then make the generator (or a refinement file) reproduce exactly what Looker validated.

## 5. Thresholds (initial `ewi_thresholds`)

| Metric | Direction | Amber | Red |
|---|---|---|---|
| `chargeback_rate_value` | higher is worse | 0.60% | 0.90% |
| `fraud_loss_rate_bps` | higher is worse | 8 | 12 |
| `refund_rate_value` | higher is worse | 4.0% | 6.0% |
| `top10_merchant_concentration` | higher is worse | 30% | 40% |

Thresholds are fictional and versioned like metrics.

## 6. Expected story on the default dataset

| Signal | Risk overview | Data risk | Conclusion |
|---|---|---|---|
| **R1**: IT chargeback rate turns red in June 2025 | Red cell in the heatmap, listed as a breach | Reconciliation, completeness and timeliness green for IT / June; only the variance check warns (a movement to explain) | **Risk event**: escalate to the risk committee |
| **D3 + D2 + D4**: settled volume drops ~40% in September 2025 | Visible dip in the line chart | Timeliness red, completeness and definition conformity failures for September | **Data event**: raise a data issue, do not report as risk |
| **D1**: duplicated group rows, ES August 2025 | Not visible (independent path) | Reconciliation break for ES / August | The parent-group product is wrong; the independent view is not affected |

R1 is a **genuine risk signal planted in clean data** (see PROJECT_SPEC §8.4). It is not a defect: no check may FAIL on it. The variance check warning is expected, because variance checks flag movements for explanation; they do not judge them.

## 7. Design rules

- One RAG palette everywhere (green, amber, red, plus grey for "not assessed"). Status is always written as text too, never shown by colour alone.
- Every measure's description names the metric id, version and definition; tiles show it on hover.
- Formats: rates in % with 2 decimals; fraud losses in bps; amounts in EUR with thousands separators.
- No logos or names of real institutions.

## 8. Build workflow

### 8a — Before the trial (no instance needed)

1. `make views` deploys the marts; `copilot dq scan --as-of 2025-10-15` fills `spb_ops`.
2. `make lookml` generates `looker/`; unit tests on the generated files pass.
3. Only now create the trial instance (`docs/GCP_SETUP.md` §12).

### 8b — With the instance

1. Connect Looker to BigQuery and the LookML project to its Git repo (`docs/GCP_SETUP.md` §12.4–12.5).
2. `make lookml-publish`; in Looker, pull, validate, deploy.
3. Claude Code, through the MCP Toolbox: validate the project, query each explore, prototype missing tiles in a personal folder if useful.
4. Export prototypes as LookML; reproduce them in the generator or a refinement file; republish. **Only LookML dashboards in Git count.**
5. `make lookml-check`: project validation + consistency test (FR-D6).
6. Collect the evidence (screenshots, video) and delete the instance before day 30 (`docs/GCP_SETUP.md` §12.7–12.8).

## 9. Acceptance

- LookML validates with zero errors and zero warnings.
- The three dashboards render and show the three rows of section 6 as described.
- Consistency test passes: Looker query results equal copilot-compiled results on sampled slices.
- Hovering a measure shows its glossary definition and version.
- Screenshots committed; 2-minute video linked in the README.
- LookML project rebuilt once from Git alone (`docs/GCP_SETUP.md` §12.9).
